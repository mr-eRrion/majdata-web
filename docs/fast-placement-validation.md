# 方向键快速放置验收

2026-09-27。依据目标程序集的 `EditorScene.Edit.NoteTrack.UpdateFastPlace` / `MoveTo`、`ProgressPanel.SetTime` 和默认轨道排序恢复行为；这是静态源码与 Web 运行证据，尚无目标窗口运行对照。

## 行为与来源

在编号轨道悬停时，左右方向键先在当前轨道放置，再按显示顺序移至相邻轨道，边界循环。默认顺序为 8→1。首次按下立即执行，持续按住时每次间隔大于200ms，左右同时按住时左键优先；不依赖操作系统键盘重复事件。使用记忆的外圈 Tap/Hold 工具，Hold 直接生成短 Hold，不进入两次点击流程。

每步用悬停拍点与下一吸附拍点的实际秒差推进当前播放头，保留悬停点相对播放头的偏移；因此跨 BPM 不能使用固定秒数，也不能直接跳至悬停点的下一拍。同拍同轨同类重复不提交、不增加历史，但仍换轨并尝试推进时间。播放中成功新增会先暂停，再推进；重复落点不暂停，播放中的定位被跳过。有歌曲时播放头夹取到歌曲范围，仍继续换轨。

源码 `NoteTrack.PlacingHold` 与 `TouchTrack._placingHold` 是独立状态；只有待完成的外圈 Hold 阻止快速放置。输入框、选择模式、轨道外、只读难度和文档替换期间不执行。窗口失焦、页面隐藏、字段获得焦点、工具/细分/难度/文档变更会结束长按。

## 浏览器适配与限制

浏览器不能移动系统鼠标，改为显示使用原音符素材的半透明逻辑光标。每次换轨保持屏幕 Y，按新时间窗口重新计算拍点；松键后保留光标，实际移动鼠标后重新定位。沿用 Web 连续吸附和有效区域命中，不复现目标30 Unity单位拍线阈值及越界后可能保留的旧悬停状态。选择模式及工具切换终止长按也是 Web 的明确交互约定。

一次编辑确认前暂停接受下一次快速放置；持续按住会在确认后继续，不积累待执行按键。此前提交未确认时短促按下再松开可能不产生新落点。圆形跨区输入仍按既有队列逐笔处理。无歌曲可继续自由编辑；歌曲上下限沿用 Web 谱面偏移模型，设备校准独立于文档，不宣称与目标 MusicOffset 下限完全等价。

## 验证

`fast-placement.test.ts` 覆盖按显示顺序循环、跨 BPM 秒差及非法轨道。全部61项单测和类型检查通过。`tests/fast-placement-browser.mjs` 在已有 Chromium 153.0.8010.12、1920×1080、DPR1、真实 WASM 内核及生产构建上通过15组流程：放置后换轨、相对时间推进、长按节奏、零 Hold、重复无历史、跨 BPM、待定 Hold 门控、焦点/模式/越界门控、失焦停止、播放中新建与重复的差异、歌曲末尾夹取、只读、撤销重做与导出重开。长按3次测得437ms，页面异常0。

# 单段 Slide 编辑与验收

2026-09-27：限定单段 `-<>w` 已通过本地生产浏览器编辑与真实 WASM 保存闭环。本文记录实现、实测和剩余限制，不代表目标程序兼容验收通过。

## 当前支持范围

同一份 `StrictSimaiParser` 与 Chart Core 识别并建模单段 `-`、`<`、`>`、`w` Slide。模型保存起点、终点、路径命令、头部类型、起点 Break/EX、独立的路径 Break，以及 `wait` 和 `move` 两段时长。解析结果保留 `moveStartSeconds = hit + wait`；显示结束时间为 `moveStart + move`。

合法识别的单段 Slide 可进入 Core 的新增、更新、删除、变换、复制粘贴、撤销与重做事务。`slide-validation-pending` 是非阻断警告，表示目标程序的运行行为尚未验证；它不代表原生兼容已经通过。若同一难度还含解析失败、未支持的 Slide 语法或其他阻断诊断，该难度仍只读，原始谱面文本保留。

## 路径与时长

起点和终点使用环形轨道 `1–8`。直线 `-` 要求终点相对起点的环形距离为 `2–6`；`w` 必须落在正对面的轨道。`<` 与 `>` 使用已提取的序列化路径表和对应端点候选。放置器不提供任意折线或自绘轨迹。

路径头默认为星形；`@` 表示 Tap 头，`!` 表示无头。起点 Break/EX 与路径 Break 分别保存，例如 `1@xb-5b[4:2]` 表示 Tap 头、起点 EX 与 Break、直线到 5、路径 Break。具体可写回形式以严格扫描器和序列化器实际接受的 token 为准。

`wait` 与 `move` 是两个独立、非负、允许为零的显式时长。拍数表达按 `beats × 4 / division × 60 / bpm` 换算；`beatsAtStartBpm` 使用音符起点 BPM，`beatsAtBpm` 使用表达中指定的 BPM，秒数表达保持固定秒长。核心序列化器只输出以下已编码的组合：

| 等待 / 移动 | 示例 | 含义 |
| --- | --- | --- |
| 起点 BPM 下等待一拍 / 起点 BPM 下移动 | `1-5[4:2]` | 等待一拍，移动两拍 |
| 指定 BPM 下等待一拍 / 同 BPM 移动 | `1-5[240#8:1]` | 两段都按 240 BPM 解释 |
| 固定秒等待 / 起点 BPM 下移动 | `1-5[0.25##8:1]` | 等待 0.25 秒，再按起点 BPM 解释移动 |
| 固定秒等待 / 固定秒移动 | `1-5[0.25##0.5]` | 等待 0.25 秒，移动 0.5 秒 |
| 固定秒等待 / 指定 BPM 移动 | `1-5[0.25##240#8:1]` | 移动拍数按 240 BPM 解释 |
| 指定 BPM 下等待一拍 / 固定秒移动 | `1-5[240#0.5]` | 等待按 240 BPM 解释，移动 0.5 秒 |

不在这些组合中的模型时长不能直接写回，序列化会拒绝。放置时跨 BPM 的点击间隔会转为固定秒数，以保留所点时间；不能用单一 BPM 拍长近似跨段秒差。属性面板编辑等待或移动秒数时也存为固定秒表达；未修改的导入音符保留原有表达。

## 放置、路径候选与模板

Slide 工具默认启用一拍起始等待，头部模板为星形，路径 Break 关闭，Wi-Fi 关闭；起点 Break 与 EX 使用外圈工具属性。

- 一拍起始开启：第一次点击确定 hit 拍点和起点轨道，移动起点自动设为 hit 后一拍；第二次点击确定终点。关闭后需要依次点击起点、等待结束拍点和终点，等待结束点击的轨道不参与路径计算。
- Wi-Fi 开启时，终点自动固定在起点对面，结束点击后直接提交。
- 普通路径在终点后打开候选面板，只列出当前端点可用的 `-`、`<`、`>`。悬停/聚焦预览，单击候选或 Enter 提交；Esc 取消整笔放置，右键只清候选。选择已有 Slide 后，属性面板能改路径、终点、头部、路径 Break、等待秒数和移动秒数；改变起点位置会整体旋转路径。Slide 中键模板套用头部与起点 Break/EX，保留路径 Break 和时长。
- 早于当前阶段起点的点击被忽略，不自动排序。右键在待放置状态中回退或取消；当前 Core 接收最终完整音符后再提交单个编辑事务。放置路径、属性修改和历史恢复都受同一难度 `editable` 标志及 Core 校验约束。源方向键快速放置排除 Slide，本地实现保留这一限制。

直接点放目前会拒绝在已有 Slide 的同拍、同起点轨道再放一条路径，并提示用户改选原音符；Core 的一般 `add` 命令与剪贴板使用通用事务路径。该同轨并行放置差异应纳入主线程浏览器验收，不据静态代码认定界面行为符合目标程序。

## 未支持内容

以下语法不进入当前可编辑 Slide DTO；包含它们时会产生诊断并使整难度只读，保留源文：

- 由多个路径命令组成的连接 Slide，以及 `*` 共享头路径；当前模型只有一个命令与一个终点。
- `?` 等未建模头型，以及 Slide 上的 `$`、`f`、`m`、`c` 等未支持修饰符。

鼠标手绘候选匹配已接入，见 [手绘验收](slide-paint-validation.md)；它识别源离散模板，不提供任意几何轨迹编辑。时间轴只按头部选择/拖动，端点与时长通过属性修改；原始 SlideEdit 纹理布局与整套目标手势尚未全部复刻。

解析器逐个识别同拍 `/` 分隔的独立音符；这不等同于 `*` 共享头语法。输出后仍由候选解析器比较难度结构、音符字段和绝对时刻；若候选重解析改变支持范围或语义，导出会失败，不会静默替换原文。

## 保存与检查点保护

只修改被编辑的 `inote_N` 字段，其他源字段和换行后缀按原文本范围保留。导出前用同一解析器重解析候选文本，并比较难度、BPM、音符种类、位置、修饰符、Slide 路径与头部、时长表达、hit、移动起点和总时长；不通过则拒绝候选。未修改的文件仍可原字节导出，其他只读难度不因单一可编辑难度而重写。

检查点恢复会重新解析原始谱面，再核对来源字段与未修改图表语义。旧 schema 3 检查点中未修改、含 Slide 的只读难度，只有在当前重解析基线已可编辑并且未修改语义匹配时才会迁移；若当前基线仍因未知或不支持内容只读，则不会解锁。

## 本地验收结果

使用已有 Chromium 153.0.8010.12，1920×1080、DPR 1，生产版本 `index-DqyGKUgG.js`、`chart.worker-BspSFETD.js`，WASM 框架 5,901,204 字节。类型检查、74 项单元测试和 WASM/前端构建通过。

`tests/slide-edit-browser.mjs` 的 10 组实际操作通过：候选悬停像素变化、模态撤销隔离、取消不留历史；默认一拍直线；选择、整体旋转、跨轨/拍点拖动、复制粘贴；手选等待与 Wi-Fi 对向端点；零等待/零移动；跨 BPM 点击时间；头部/路径 Break/时长属性与未改表达保留；同拍同轨 `/` 独立事件；圆形区域圆弧放置、中键模板、删除及撤销；端点/路径/起点属性和修改后的检查点恢复。每组保存通过真实 Worker 候选重解析，重开后比较模型字段和绝对时刻。报告见 [10 组流程](results/2026-09-27/slide-edit.json)，界面见 [路径候选](results/2026-09-27/slide-picker.png) 与 [编辑结果](results/2026-09-27/slide-edit.png)。

`tests/slide-roundtrip-browser.mjs` 的 6 种时长和 24 种修饰组合共 30 例通过真实 WASM 往返，见 [序列化结果](results/2026-09-27/slide-roundtrip-edit-enabled.json)。`tests/slide-browser.mjs` 的 10 个支持样例、3 个不支持难度、原字节导出、多难度编辑重开和 schema 3 恢复通过。`tests/mixed-preview-browser.mjs` 的正负偏移、反复 seek、0.5/1/2 倍速及循环通过；导入等待改为确认新文件名，避免读到上一文件的旧面板状态。

以上结果证明 Web/Core 使用固定 MajSimai 版本的本地模型与保存闭环。目标 Visual Maimai / MajdataPlay 的原生运行画面、播放等待/移动/结束与 seek 中段行为仍需要独立证据；`slide-validation-pending` 在取得该证据前继续保留。连接/共享头和 Slide 编辑性能尚未完成验收；后续手绘匹配验收另见上述记录。

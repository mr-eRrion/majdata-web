# Visual 碰撞检查验收

## 范围与来源

按固定程序集的 `ChartWatcher.Check` 实现 codes 0–8；源码、边界和字段来源见 [检查器来源](chart-warning-source.md)。输入为当前可编辑难度的拍域模型，检查结果是 Worker 生成的显示数据，不进入原始文档、撤销事务或恢复检查点，也不混入语法诊断。编辑完成后检查失败会显示“未完成检查”，不能把已提交的编辑回报为失败。

检查使用原程序默认 0.12 秒严重范围与 0.20 秒提醒范围，没有读取原生 PlayerPrefs。只读难度未完整建模，明确不检查；原 Visual 导入器无法解析的时长组合、超出可保证精度范围的数据也标为未检查，不当成无告警。当前时间位置来自 Web 的规范化拍域；本实现不模拟任意源文件的全部 Visual 词法导入过程，尤其不据此宣称网格语法或所有导出文件已通过原生兼容验收。

支持路径的 87 个通行区域事件直接来自 29 条序列化路径；`warningLength` 按源 float32 运算单独计算，原预览长度和几何保持不变。Wi-Fi 按源常量 0.85073 生成三个区域事件。连续段使用各段自身起点旋转区域编号，共享头的各分支单独参与移动区间检查。

时长按 Visual 的导入表达恢复为 `TimeData` 再应用 BPM 表；不改 Core 的 Simai 播放语义。秒数和指定 BPM 表达式保留原程序的整数截断与 float32 顺序。跨 BPM 时两者可不同，界面明确提示此边界。

源码的零时长三支覆盖和有条件无头过滤按实际分支保留；不是把它们替换为一般几何碰撞定义。三支覆盖搜索使用位集合去除排列重复，但结果仍按同拍同 code 去重。

## 导航与界面

结果每页最多50项，列出时间与原因且全部可翻页访问，点击可定位；菜单的上一处/下一处告警复用同一结果，空结果与未检查时禁用。Web 在秒域按时间排序、跳过当前时间 1ms 范围，并在两端回绕；同拍的多个 code 为同一个导航停靠点。源 Next/Last 疑似混用拍与秒，此处采用正确时间排序并明确记录差异，原生导航行为仍没有运行对照。

结果列表置于工具面板，尚未复刻原 CheckResultTrack 的时间轨图标和悬停样式。原生同视口、参数设置和完整操作对照仍属于 V2/V4 的未决项。

## 本轮证据

- 174项单测通过，包含58组独立C#金标。原始 `ChartWatcher`、`TimeData`、`BpmData` 与设置类原样编译，最小stub仅提供外围容器和Unity替代；602条输出的拍点/code/severity逐项相同。40组固定种子混合谱涵盖Touch、Hold、共享/连续与Wi-Fi，另18组覆盖Wi-Fi的1ms、严重和最大阈值以及EX。输入和输出保存在 [金标fixture](../fixtures/visual-maimai/warning-oracle.json)，重跑方法和源码哈希见 [探针说明](../tools/visual-assets/warning-oracle/README.md)。此证据检查拍域算法，不覆盖原始字符串导入器或原生UI。
- 另以80组固定种子的区间组合，对优化后的三支覆盖搜索与独立穷举三元组逐项比较，包含零时长。29条路径的float32长度与独立C#距离/顺序累加计算 [全部相同](results/2026-09-27/warning-length-oracle.json)（ULP差0），87条区域事件由生成工具检查。
- 生产浏览器9组流程通过：跨BPM三种告警、前后导航与回绕、列表定位、删除/撤销重算、检查点不包含派生结果、候选导出重开/刷新恢复，只读谱面显示未检查并保持原文、Visual不可解析的时长组合不阻断正常编辑/撤销，以及80条结果的完整分页访问。见 [结果](results/2026-09-27/visual-checks.json) 与 [截图](results/2026-09-27/visual-checks.png)。截图已目检，文字和按钮未见裁切。
- 既有16组编辑菜单流程再次通过，见 [回归结果](results/2026-09-27/visual-checks-menu-regression.json)。最初功能验收入口为 `index-BjnWwlz7.js`；最终分页版 `index-BdIOoNSY.js` 的9组检查流程已重新通过，Worker为 `chart.worker-CNE-G0AS.js`。

## 性能审查

第一轮千音符均匀谱的热导入到就绪P95为829.5ms，路线保存382.8ms，超过导入预算；该失败数据保留在 [优化前结果](results/2026-09-27/warning-performance-uniform-before.json)。检查器成对比较重复执行通用分数校验和约分，改为对已验证输入做精确整数交叉乘法：安全整数范围内直接比较，超出时使用BigInt；不改变Core通用运算或检查含义。

生产版 `index-DjIbxyf0.js` 同负载复测：热导入至就绪133.8ms、Worker响应79.5ms、保存至快照和两帧68.1ms、输入反馈33.9ms、帧P95 16.8ms，超过33.3ms的帧比例为0。见 [均匀首次复测](results/2026-09-27/warning-performance-uniform-before-pagination.json)。均为无歌曲的实际浏览器测量，不替代完整音频内存和原生运行对照。

密集谱面产生1,273条检查结果，首次优化后的旧轮询口径导入P95为219.8ms。结果列表改为每页50项后，同口径仍为213.9ms；分页减少了首屏DOM数量，但没有仅凭该变化宣称导入预算通过。两次原始数据见 [分页前](results/2026-09-27/warning-performance-dense-before-pagination.json) 和 [分页后旧口径](results/2026-09-27/warning-performance-dense-pagination-polled.json)。后续脚本增加页面内部的文件change→新文档v0/皮肤就绪→两帧时间，同时保留自动化轮询口径，避免把轮询往返当作产品处理时间。

最终分页版密集谱面同步采样：页面内部热导入P95为130.4ms，旧自动化观察口径为214.1ms，Worker响应83.3ms；输入反馈33.7ms、保存完成66.3ms、帧P95 16.8ms、长帧比例0。检查成功并产生1,273项结果，见 [密集最终结果](results/2026-09-27/warning-performance-dense.json)。这说明旧口径包含显著的自动化往返开销；保留两种数值，不将其变化全归于分页优化。

最终均匀谱面产生1,300项检查结果，页面内部热导入P95为129.9ms，旧轮询口径213.9ms；Worker响应82.8ms、输入反馈32.8ms、保存完成66.2ms、帧P95 16.8ms、长帧比例0，见 [均匀最终结果](results/2026-09-27/warning-performance-uniform.json)。两种负载在最终版本、相同页面内计时条件下均达到约定的热导入、帧和输入预算。

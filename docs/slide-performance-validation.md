# 共享头与连续路线性能验收

2026-09-27 在 Apple M4/macOS arm64、已有 Chromium 153.0.8010.12、headless 前台、1920×1080、DPR 1 下测量，不作 CPU/网络节流，不加载歌曲。以下数据来自生产入口 `index-TYMxAMaV.js`（SHA-256 `b9e912cbf599ce22ee889d0f55225ecdc4a4eeef71b07c0074fe81729cbf75c8`），Worker 为 `chart.worker-aspj87W7.js`。这次测试补齐条带密度和真实路线编辑负载，不代替有歌曲 seek、长音频内存或原生画面验收。

[固定生成器](../fixtures/charts/generate-connected-load.mjs) 构造 5 分钟、1,000 个逻辑音符：810 Tap、90 Hold、100 Slide。每个 Slide 有两支四段路线和一支 Wi-Fi，总计 300 支、800 个非 Wi-Fi 片段、100 支 Wi-Fi。每支等待 0.5 秒、总移动 8 秒，包含 Break/EX。均匀样例将 Slide 起点分散在 0–291 秒；密集样例先在 0–3.96875 秒放 20 个 Slide，其余延伸到 291 秒。所有 Hold 在 300 秒前结束。

| 指标 | 均匀分布 | 短时密集 |
| --- | ---: | ---: |
| 帧间隔 P95，连续播放 15 秒/900 帧 | 16.7 ms | 16.7 ms |
| 帧间隔超过 33.3 ms 比例 | 0 | 0 |
| 热导入至界面就绪 P95，10 次 | 114.0 ms | 99.4 ms |
| Worker 导入/编译 P95，10 次 | 61.5 ms | 53.6 ms |
| 实际可见条带网格峰值 | 20 | 151 |
| 路线保存输入反馈 P95，10 次 | 34.2 ms | 33.5 ms |
| 路线保存到快照和两帧 P95，10 次 | 49.9 ms | 49.4 ms |
| 无歌曲 seek 到两帧 P95 | 34.1 ms | 34.0 ms |

[测量脚本](../tests/slide-connected-performance-browser.mjs) 导入 12 次，前两次暖机后排除；界面就绪时间从原生文件 change 事件计时，等待新文件快照、皮肤就绪和两个动画帧，包含自动化等待的开销。Worker 指标只包含 postMessage 到快照响应，不混用这两种口径。编辑测试通过真实路径属性弹窗删除末段、保存，再撤销，逐次核对版本和片段数；输入反馈从 pointerdown 到两个动画帧计时，保存完成另由 Worker 快照确认。

可见条带计数是实际 Pixi 非零透明度网格数量，不含 Wi-Fi 箭头、星星、头部或网格内部三角形。只有测试显式设置 DOM 属性时才读取计数。连续播放采样之外，在每个 Slide 出现时间后遍历整个五分钟谱面：其余条带数量随运动只会减少，因此出现点是数量峰值候选。两种方法得到相同峰值。该数值不代表视觉上可分辨的箭头个数。

两个负载的本机帧、输入和热导入数值达到约定预算；无歌曲 seek 不计入“已载入歌曲”的定位预算。密集截图审查发现并修复了近折返接头的条带尖刺，以上为修复后的完整复测数值。不得以帧率合格替代画面正确。

原始结果：[均匀](results/2026-09-27/slide-performance-uniform.json)、[密集](results/2026-09-27/slide-performance-dense.json)。复现需先运行本地生产预览，`BROWSER_EXECUTABLE` 指向已有 Chromium，两种负载串行执行：

## 截图审查与网格修复

密集样例在 3.801 秒出现长尖刺：2.71875 秒起、6 号起点的圆弧分支 `<8>2<4>6[0.5##8]` 第一段进度约 0.582106，源半单位尾点取整令末端相邻方向接近反向。资源为 id 1263（`1＞3`），renderer 0 截取点 0–21，弧长 3.16593225649 取整到 3.0，末弦长 0.15075870980，对应伸缩系数 -0.10064789430，形成约 178.20° 折返。原 Web miter 相对半线宽放大约 63.7 倍，网格最大半径达 29.0475，远离半径约 4.8 的中心线。该问题是网格连接算法的缺陷，不是解析时长或路径坐标错误。

`slide-mesh.ts` 保留原始中心线、尾点取整、UV 距离及正常接头；仅当 miter 长度超过四个半线宽时，拆分入/出边并填充外侧三角形形成 bevel。四个半线宽是 Web 网格的数值限幅选择，不声称来自 Unity 设置；原生像素对照仍待验。真实圆弧尾点及其镜像回归覆盖两种转向，已有直线、90°拐角和退化尾点测试保持通过。最终 97 项单测、类型/素材检查和生产构建通过。

[修复前截图](results/2026-09-27/slide-load-dense-before-join-fix.png) 与 [修复后截图](results/2026-09-27/slide-load-dense-peak.png) 使用同一谱面时间和视口，已人工检查尖刺消失，纯几何复现的最大半径降至 5.2492；[均匀峰值截图](results/2026-09-27/slide-load-uniform-peak.png) 另行保留。没有据此宣称已完成原生高密度遮挡和层级对照。

## 五分钟音频与波形就绪后的定位

后续生产入口 `index-BYynT38X.js` 使用同一1k样例，加上实际解码的300秒、48kHz、双声道PCM16静音WAV。临时文件通过真实歌曲入口加载；32个波形Worker请求/响应覆盖全部14,400,000帧，无音频或页面异常。文件在测试后清理。报告将谱面导入（加载歌曲之前）与有曲播放/定位/编辑分开，不拿前者冒充带媒体导入耗时。

均匀/密集两种负载的帧P95均为16.7ms，超过33.3ms的比例均为0，可见条带峰值仍为20/151。已载入歌曲定位P95分别34.1/33.5ms，输入反馈33.5/33.4ms，路线保存到快照和两帧49.9/48.7ms；满足约定的本机定位、帧和输入预算。每个定位目标都在计时的两个动画帧内检查软件播放位置；整曲出现点遍历也检查实际到位。播放时长仅覆盖15秒性能窗口，并非完整五分钟实时播放，更不是物理音画同步测量。

[均匀有曲结果](results/2026-09-27/slide-performance-uniform-audio.json)、[密集有曲结果](results/2026-09-27/slide-performance-dense-audio.json)。复现给原脚本追加 `--audio`，密集模式再加 `--dense`；临时音频只为测量生成，不发布用户媒体。

## 碰撞检查接入后的复测

最终生产入口 `index-BdIOoNSY.js` 在上述1k均匀/密集负载中分别生成1,300/1,273项碰撞结果。页面内部记录文件change→对应新文档v0与皮肤就绪→两帧，热导入P95为129.9/130.4ms；同时保留旧自动化轮询观察口径213.9/214.1ms。Worker响应82.8/83.3ms、输入反馈32.8/33.7ms、保存至快照和两帧66.2/66.3ms、帧P95均16.8ms且长帧比例0，可见条带峰值仍20/151。两种计时的定义与优化前失败记录见 [检查器性能审查](visual-checks-validation.md)，不把轮询开销减少宣称为产品优化。

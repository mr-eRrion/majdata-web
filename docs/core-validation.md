# Chart core validation

`packages/chart-core` owns the mutable chart document in the Worker. It consumes the normalized DTO from the single MajSimai parser bridge; it does not parse Simai source syntax itself. Editable difficulties support Tap, Hold, Touch and Touch Hold. Touch stores its area letter separately from its index: A/B/D/E use positions 1–8 and center C uses position 0. Ring notes remain positions 1–8. EX Touch and Touch Hold, and Touch Hold with the bare short duration, are rejected. Unsupported or partially understood chart content remains attached to a read-only difficulty.

The public entry point is `packages/chart-core/src/index.ts`. It exports `ChartEngine`, exact rational helpers, `beatToSeconds`, `secondsToBeat`, `bpmAtBeat`, `holdDurationSeconds`, `compile`, `queryVisible`, and `transformNotes`. Display note seconds are relative to chart time; `DisplaySnapshot.firstSeconds` is a separate song offset. Hold and Touch Hold share the same duration conversion: a duration encoded in beats at its starting BPM uses that BPM for the full interval, even if later chart events change BPM. Explicit-BPM, fixed-seconds, and zero-duration short Holds retain their expression kinds; a short Touch Hold is unsupported.

Edits validate a candidate chart and its serializable source size before changing the document, version, generated-ID counter, or history. Undo and redo retain note/BPM/end-beat deltas and one-field metadata deltas, capped at 100 transactions. Failed commands leave those values unchanged. `&first` edits require document-level editability and every imported difficulty to be editable. Candidate snapshots compile before commit so timing overflow cannot leave a partial transaction.

An unchanged document exports its retained input bytes directly, including UTF-8 BOM and CRLF. Invalid UTF-8 remains raw-download-only. Editing replaces only a changed `&inote_N` value, descriptive metadata value, or `&first` value. Missing known metadata fields and `&first` are appended together at end-of-file; all unrelated source fields and untouched difficulties retain their original text. Metadata edits are restricted to `title`, `artist`, `des`, `lv_1`–`lv_7` and `des_1`–`des_7`, and values must be single-line. Duplicate or multiline known metadata stays read-only at the core metadata boundary; parser-level global read-only decisions remain in effect independently. Generated candidates are passed back through the injected parser and checked for field structure, metadata, difficulty state, BPM events, exact beats, note kinds/positions/Touch areas/modifiers/durations, terminal beat, and parser-derived timing. Parser or comparison failure rejects export and leaves the document modified.

`transformNotes` returns an update batch for the selected Tap/Hold/Touch/Touch Hold notes; callers submit it as one normal `update` transaction. It leaves timing, duration, modifiers and Touch area letters unchanged. The mapping rules are recorded against the archived MajdataEdit `Mirror.cs` at commit [`963812b6ec3e023360993f50fbbd7f51e9de9180`](https://github.com/LingFeng-bbben/MajdataEdit/blob/963812b6ec3e023360993f50fbbd7f51e9de9180/Mirror.cs) (SHA-256 `f7e4edcba04c87f7662a50e54479e3cf20bf65f7685375d16ab5509f2abb36d8`; upstream license GPL-3.0). This implementation uses structured position mappings rather than copying its source-text conversion routine. Horizontal and vertical mirrors use distinct D/E Touch phases; center C is fixed. Clockwise and counterclockwise 45-degree rotations use the normal eight-position cycle for all numbered areas. These are compatibility-reference rules, not player-runtime evidence.

External checkpoints use schema v2 and contain document state only: they contain no audio or undo/redo history. Older v1 recovery records are incompatible and are not migrated. Restore checks source bytes against text, verifies source ranges and fields by reparsing the retained original source, preserves the original read-only state of each difficulty and the metadata editability baseline, then clears history. Existing multiline metadata may be restored only unchanged; editable metadata remains single-line. The next edit begins a new bounded undo history.

The implementation mirrors the parser's current source bounds: 2,000,000 UTF-16 code units and 100,000 notes per difficulty. Exact rational operations cap reduced numerators and denominators at JavaScript's safe-integer limit, matching the parser DTO's exact-integer contract. Serialization uses an exact subdivision when possible and otherwise expands the interval into exact fractional-beat cells; it rejects a generated chart above 1,000,000 cells rather than rounding beats.

Run the focused checks with:

```sh
pnpm exec vitest run packages/chart-core/tests
```

The tests use the self-authored `fixtures/charts/baseline.maidata.txt` and hand-authored normalized parser DTOs. They exercise time conversion, atomic batches, source preservation, metadata append/undo/redo and multiline-readonly behavior, Touch serialization and reparse comparison, checkpoint validation, and the transform inverse/cycle rules. This verifies the TypeScript contract and generator against fixture DTOs; it is not an independent test of the real C# WASM parser or the target player's behavior. Worker integration must rerun these flows with the pinned C# parser. Slide/Wi-Fi geometry remains read-only without player runtime evidence; see [geometry validation](geometry-validation.md).

# BPM 事件选择与剪贴

## 来源与实现边界

原生选择与剪贴行为依据 [R3 `EditorScene_Select_SelectArea.cs`](../.tools/visual-reverse/r3/EditorScene_Select_SelectArea.cs) 中的 `Copy`、`Cut`、`Paste` 和 `Delete`。Web 将 BPM 事件按精确拍点作为选择键；导入谱面中同拍的多个 BPM 声明会作为一组选中、复制或剪切。剪贴板把所选音符与 BPM 一起按最早拍点对齐，粘贴预览取消不会提交历史记录；确认后由一次 Worker 编辑事务提交混合音符与 BPM 改动。

删除会保护第 0 拍 BPM，但同次选中的音符仍会删除。粘贴到已有 BPM 拍点时，以剪贴板中最后一个该拍事件覆盖目标拍的声明；未被覆盖的原声明保持不变。菜单“全选”仍只选择音符。只读难度可选择和复制，剪切、删除及粘贴不可用；切换难度或导入新谱面会清除 BPM 选择。

粘贴的 BPM 到达或越过原 E 拍点时，将 E 延至最后一个 BPM 后一拍，保证严格解析器要求的独立结束格；修改结尾之前的 BPM 不改变 E。混合粘贴的预览按粘贴后的 BPM 表重新计算音符秒数。检查点保持 schema 5，没有新增持久化字段。

当前图表模型没有拍号 keyframe。原生导入器为 maidata 设置默认 4/4，导出器不输出拍号；Simai `{division}` 是节奏分割数，不能作为拍号处理。因此本轮不提供拍号选择或剪贴。

## 浏览器验收

主代理在已有 Chromium 153.0.8010.12、1920×1080、DPR 1 上运行 `tests/bpm-clipboard-browser.mjs`，以真实 Worker 快照和 WASM 导出重开核对以下四组流程，页面异常为 0：

- BPM 单独选择、复制、预览取消、粘贴到旧 E 之后、一次撤销 / 重做、导出重开；未修改难度的源文本保持一致。
- 音符与 BPM 混合剪切 / 粘贴，按共同最早拍点对齐，一次撤销恢复两类事件，重做与导出重开的完整快照一致。
- 第 0 拍 BPM 删除 / 混合剪切保护，同拍粘贴覆盖后重新计算音符时间，导出重开保持一致。
- 混合框选、难度切换、导入时清理选择与粘贴草稿、全选只含音符、只读难度禁止修改。

记录见 [浏览器结果](results/2026-09-27/roadmap-followup/bpm-clipboard.json)；主代理检查了 [选择截图](results/2026-09-27/roadmap-followup/bpm-selection.png) 和 [粘贴预览](results/2026-09-27/roadmap-followup/bpm-ghost.png)。179 项单元测试包含事务失败不提交、混合操作撤销重做、同拍最后值覆盖与既有重复声明保留。

独立验收曾发现 BPM 与 E 同格时真实解析器拒绝导出，而旧手工解析夹具错误接受 `(240)E`。主代理修复 E 延后逻辑，并同步夹具的独立结束格预期，保留严格导出语义检查；没有修改 WASM 解析器。此结果只覆盖本地 Web 闭环，不代表原生操作或像素对照已经完成。
